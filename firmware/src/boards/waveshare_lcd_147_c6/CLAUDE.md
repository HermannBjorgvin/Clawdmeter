# LCD-1.47 (C6) — `waveshare_lcd_147_c6`

Hardware notes for this board. Shared firmware rules are in `firmware/CLAUDE.md`.

The C6 sibling of `waveshare_lcd_147`: the same 172×320 **JD9853** IPS panel on plain 4-wire SPI, run rotated so the UI gets a **320×172 landscape** canvas, and the same AXS5106L touch, on an ESP32-C6FH8 (8 MB embedded flash, **no PSRAM**). The display, touch and button code matches the S3 port line for line; only the pins differ, so a fix to one usually belongs in both. Pin map from Waveshare's docs (docs.waveshare.com/ESP32-C6-Touch-LCD-1.47), confirmed on hardware, except BOOT (below).
- Display: JD9853 via SPI (CS=14, SCLK=1, MOSI=2, DC=15, RST=22, BL=23). Driven by Arduino_GFX's `Arduino_ST7789` **plus the vendor register sequence** in `jd9853_reg_init()`, pushed after `gfx->begin()`. Without that sequence the panel stays dark. Constructed portrait (172×320) with `col_offset1 = 34`, then `setRotation(1)`; `Arduino_TFT::setRotation` maps that offset onto the correct axis. Inversion comes from the vendor sequence's closing `INVON` (0x21); `ips` only changes how `invertDisplay()` reads its argument.
- Brightness: LEDC PWM on the backlight GPIO (no panel brightness command).
- Touch: **AXS5106L** @ I2C 0x63 (SDA=18, SCL=19, INT=21, RST=20), vendored inline reader — 14-byte burst from reg 0x01, finger count in byte 1. Needs a long reset pulse (200 ms low / 300 ms settle). Landscape maps raw portrait coords by swapping axes with no mirroring; raw coords are clamped to the panel first.
- IMU: QMI8658 @ 0x6B on the same bus. Initialized for bus health only; rotation is off (fixed orientation, and no PSRAM for the rotation strip).
- Battery: ETA6098 standalone charger (no I2C, no CHG/STAT pin) and VBAT → 3.0× divider (R21 200K / R22 100K) → GPIO0. Charging/VBUS state is unknowable and reports false.
- **Battery is off by default** (`BOARD_HAS_BATTERY 0`): with no cell, VBAT is whatever the charger leaves on the pin. On the tested C6 unit that is ~4.2 V, a full battery; on the S3 kit it differs between units (one reads empty, one full). Only a reading under 3.0 V counts as "no battery", so a missing cell can't be told from a real one. With it off, `power_hal_battery_pct()` stays -1, so neither the screen nor the BLE battery service reports one. Set it to 1 if a cell is wired to VBAT.
- Buttons: **BOOT (GPIO 9) is the only readable key**, not the GPIO8 Waveshare's docs list. It takes the PWR role (brightness / hold-3s-release pairing) — without it the device could never be paired. So `BoardCaps.button_count == 0` and the HID Space / Shift+Tab paths never fire on this board.
- **No hold-to-power-off**: there is no power-hold latch to drop, and GPIO 9 is the C6's boot strapping pin — an ext0 LOW-level wake would sample it while still held and drop the chip into USB download mode.
- No IO expander, no codec/buzzer. USB is the C6's USB-Serial-JTAG: the env needs both `ARDUINO_USB_CDC_ON_BOOT=1` and `ARDUINO_USB_MODE=1`. 8 MB flash, `default_8MB.csv`.
- No PSRAM: the `screenshot` serial command is compiled out (`LV_USE_SNAPSHOT=0`), and Clawd plays corner acts instead of full-size scenes (`docs/clawd-director.md`). The simulator's `lcd147` cell has this board's size and caps but builds with PSRAM, so it shows the meters layout, not the C6's Clawd; check those on the device by eye.
- UI: too short to stack the usage cards, so `layout_compute()` puts them side by side (the landscape-strip rule in `layout.cpp`).
